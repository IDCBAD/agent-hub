# Agent Hub 原型评审与设计决策

## 1. 评审范围

评审对象为 `agent-hub-prototype.html`。原型已经覆盖以下交互：

- Agent 总览
- Agent 配置详情
- Skill 搜索、筛选和启停
- 手动添加 Agent
- 重新扫描
- 配置目录与文件打开反馈
- 基础设置展示

这说明原型不是单纯视觉稿，已经能够表达主要操作路径，可以作为产品讨论基础。

## 2. 原型中应当保留的部分

### 2.1 克制的桌面工具气质

当前界面没有营销式装饰，信息密度和按钮尺寸适合本地开发工具。后续实现应继续保持这一点。

### 2.2 Agent 卡片中的路径与资源数量

路径、Skill、MCP 和 Prompt 数量比品牌介绍更有管理价值，应当继续作为 Agent 摘要信息，但需要增加发现状态和最近同步时间。

### 2.3 配置树

配置树能直接回答“这个 Agent 由哪些文件组成”，与 Agent Hub 的核心目标一致。它应扩展成通用 Resource Map，而不是只展示文件目录。

### 2.4 手动添加作为自动发现的补充

自动发现不可能覆盖自定义环境变量、便携安装、WSL 和私有 Agent。手动添加不是边缘功能，而是发现系统的必要兜底。

## 3. 需要调整的部分

### 3.1 合并“总览”和“配置详情”的上下文

原型将 Agent 总览与配置详情设为两个一级导航。用户从卡片进入详情后，需要在另一个页面重新选择 Agent，实体上下文被中断。

v2 改为：

```text
Agent Inventory → Selected Agent → Resource Map
```

Agent 列表和当前 Agent 详情同时存在。切换 Agent 时右侧内容原位更新。

### 3.2 从卡片墙调整为可扩展列表

卡片墙适合 3–6 个 Agent，但产品要解决的是“本地 Agent 越来越多”的问题。超过 10 个以后，卡片会造成大量滚动和重复信息。

v2 使用紧凑 Agent 列表，支持：

- 搜索
- 状态筛选
- 快速比较版本、路径和最后发现时间
- 20–50 个 Agent 的连续浏览

### 3.3 MVP 不把 Skill 提升为一级实体

第一阶段的核心是发现 Agent 及其资源拓扑。Skill、MCP、Prompt 暂时统一为 Resource Kind，避免在尚未建立安全写入和部署模型前暗示“启停”已经可靠可用。

后续引入 Artifact 与 Binding 后，再将 Skill、Prompt、MCP 提升为可复用资产。

### 3.4 细化状态语言

“已配置”不足以描述实际情况。MVP 至少需要：

| 默认中文文案 | 内部状态码 | 含义 |
|---|---|---|
| 正常 | `ready` | 可执行文件和配置目录都已验证 |
| 仅发现配置 | `config_only` | 找到配置，但未确认可执行文件 |
| 有变化 | `changed` | 文件在 Agent Hub 外部发生变化 |
| 路径失效 | `missing` | 已记录路径不再存在 |
| 无法识别 | `invalid` | 目录存在，但不满足适配器验证规则 |
| 已停用 | `disabled` | 用户保留记录但关闭扫描 |

### 3.5 展示发现证据

自动发现必须可以解释。详情页应展示：

- 发现来源
- 可执行文件路径
- 配置根路径
- 核心特征文件
- Adapter 版本
- 最后扫描时间
- 置信度

否则用户无法判断误报来自哪里。

## 4. v2 视觉方向

### 4.1 主题

定位为“安静、清晰的个人 Agent 工作台”。视觉基线来自项目提供的 Notion Design 文件，后续 UI 不再自行引入另一套字体或结构色。

### 4.2 设计 Token

| 角色 | 色值 | 用途 |
|---|---:|---|
| 暖纸背景 | `#F6F5F4` | 应用画布和侧栏 |
| 白色表面 | `#FFFFFF` | 卡片、表格和输入框 |
| 近黑正文 | `rgba(0,0,0,0.95)` | 标题和主要内容 |
| 暖灰正文 | `#31302E` | 次级正文 |
| Notion 蓝 | `#0075DE` | 唯一结构强调色、主操作和当前选择 |
| 细分隔线 | `#E6E6E6` | 卡片边框与分隔线 |

字体角色：

- 所有标题与正文：`NotionInter / Inter / 系统无衬线`
- 标题通过 600–700 字重和负字距建立层级，不使用装饰字体
- 只有真实文件路径、命令和 ID 可以使用等宽字体
- 小标签仍使用同一字体家族，不使用像素感或全大写技术面板字体

完整规则见 [`docs/design-system.md`](design-system.md)。

### 4.3 视觉签名：资源关系

```text
Agent 程序 ───── 配置目录 ───── 已发现资源
```

它不是装饰，而是 Agent Hub 的核心数据关系：

- Agent 程序是否存在
- 配置目录是否可访问
- 已索引多少资源
- 哪个节点存在异常

关系线使用唯一结构强调色 `#0075DE`。绿色、橙色等只用于小面积状态提示，不参与布局结构。

### 4.4 中文优先

- 默认界面、导航、按钮、状态、空状态和错误信息全部使用中文。
- Agent、Skill、MCP、SQLite、PATH、JSON、TOML 等约定俗成或不可替代的技术名词可以保留。
- 面向用户的概念不直接显示 `Runtime`、`Config root`、`Discovery evidence` 等内部术语。
- 内部 DTO、数据库状态码和代码标识可以使用英文，但必须通过展示层映射成中文。
- 多语言能力通过文案键实现，不能把英文硬编码到 React 组件中。

## 5. 交互原则

1. 首屏首先回答“哪些 Agent 正常，哪些需要处理”。
2. 用户选择 Agent 后，选择状态持续保留。
3. 所有路径都能复制，但只有已验证的资源 ID 能被打开。
4. 敏感资源只显示结构和风险标记，不显示内容预览。
5. 外部文件变化先提示重新读取，不静默覆盖。
6. 空状态必须提供下一步：重新扫描或手动添加路径。
7. 后续写入操作使用一致动词：预览变更、应用、验证、回滚。

## 6. 原型与生产实现的边界

v2 原型用于验证信息结构和视觉方向，其中的扫描、路径打开和筛选是模拟行为。生产实现必须通过 Tauri IPC 调用 Rust 用例，不能把原型中的浏览器状态逻辑直接迁移为实际文件操作。
